# 想法池

这个文件记录“可以做但还没排进当前计划”的扩展。未来的 AI 或队友可以从这里挑一个，按 `AGENTS.md` 的流程认领，写进 `docs/PLAN.md`，再动手。

## 使用规则

1. 每个想法有 ID，格式 `I-NNN`。
2. 状态用 `backlog`、`doing`、`done`、`dropped`。
3. 认领时把状态改成 `doing`，在 `docs/PLAN.md` 加任务，在 `docs/WORKLOG.md` 记录。
4. 做完改成 `done`，把产出路径写在这里。
5. 不做就写原因，不要静默删除。

当前主线是“学术概念图的时序挖掘”：一个概念如何出现、增长、爆发、衰退、复活、被其他概念替代，以及下一阶段的上升概念。对应 `docs/PLAN.md` 的 M0 到 M4。

下面这些想法都服务于这条主线，按“先便宜后贵、先描述后预测、先无新数据后有新数据”排序。

## I-001 概念演化卡片与时间线

一句话：给定一个概念，展示它第一次在语料中出现、哪几年爆发、什么时候到达峰值、有没有衰退或复活、邻居概念怎么换、每个阶段的代表论文。

方法：复用 `series.py` 的逐年计数和 `mine.py` 的生命周期事件，按年份聚合 top 论文和 top 邻居。卡片只放五个数字和一张折线图，不要堆表格。

数据：M1 的全量语料。

评估：不需要新指标。用黄金案例检查事件年份是否合理。

风险：信息过载。卡片上最多五个数字、一张图、三条代表论文。

入口：`src/concept_life/app.py`。

什么时候做：M2 事件检测跑通之后，半天。

## I-002 趋势预测：下一阶段上升概念

一句话：给定 T 年以前的图，预测 T 到 T+2 年哪些概念的占比会进入增长 top-k。

方法：每个概念构造特征，包括过去三年的占比、占比增长率、爆发分、度数、社区大小、邻居的平均增长率、邻居换手率。模型用逻辑回归或梯度提升。标签是未来窗口的占比增长排名前 k。

基线：历史频率、历史增长率、随机。

指标：precision@k、NDCG@k。至少三个时间窗，报告均值和方差。

数据：不需要新数据。

风险：上升的定义会决定结果。绝对增长偏向大概念，相对增长偏向小噪声。建议同时报告两种，并在配置里写清楚用哪一种。

入口：`src/concept_life/predict.py`。

什么时候做：M3 的核心，一天。

## I-003 生命周期聚类与早期预测

一句话：把概念按生命周期形状聚类，比如闪亮型、慢热型、常青型、复活型，然后用前两年的特征预测它属于哪一类。

方法：特征包括首次出现年份、峰值年份、活跃年数、爆发分、邻居换手率、社区切换次数、占比曲线的斜率。聚类用 K-means 或高斯混合，聚类数用 silhouette 选。分类用逻辑回归或随机森林，严格按时间切分。

评估：silhouette、案例检查、早期分类的 F1 或 AUC。

数据：不需要新数据。

风险：聚类标签是人为命名的，容易过度解读。每个类型至少配两个案例。

入口：`src/concept_life/mine.py` 加特征，`predict.py` 加分类。

什么时候做：M3 之后，一天。

## I-004 候选替代检测

一句话：找出这样的概念对，A 在衰退，B 在上升，而且 A 和 B 在图上足够相似，于是 B 是 A 的候选替代。

方法：先用逐年占比序列算 A 和 B 在 A 峰值之后的负相关，再用共享邻居、同社区、概念嵌入相似度做过滤，最后用“负相关强度乘相似度乘时间重叠”打分。输出叫候选替代对，不叫替代。

评估：top-10 人工判定 precision，两到三个人打分；基线用随机对、纯共现对、纯负相关对。

数据：不需要新数据。

风险：相关不等于因果。海报上写 candidate replacement，并给一个反例。

入口：`src/concept_life/mine.py`。

什么时候做：M3，一天。这是用户最初想法里“被其他概念替代”的直接实现，优先级高。

## I-005 Citation 概念脉络与学习路径

一句话：用论文引用边构造有向概念图，给定目标概念，挖一条从基础到目标的先修链，或者生成一条学习路径。

方法：用 OpenAlex 或 Semantic Scholar 按 DOI 补引用边。对每条“论文 A 引用论文 B”，把 B 的概念当作 A 概念的先修，构造有向图。给定目标概念，反向走图，用路径强度、时间顺序、共现强度排序，输出五到八个概念的链条。学习路径可以用拓扑排序或贪心覆盖。

评估：方向一致性，路径上相邻两个概念，后者引用前者的比例；专家评分，两到三个人给十条路径打一到五分；基线用随机路径、纯时间序、共现频率。报告 inter-rater agreement。

数据：需要新数据源。Acemap 只给 `referenced_works_count`，不给引用列表。用 OpenAlex 的 `referenced_works` 或 Semantic Scholar 的 references。

风险：Acemap 概念 id 和 OpenAlex 概念 id 不一定对得上，要对齐；抓取和评估都耗时。只有时间富余才做。

入口：新建 `src/concept_life/lineage.py` 和 `src/concept_life/ingest_openalex.py`。

什么时候做：M3 之后，一到两天，且必须在周日晚上之前决定。

## I-006 时序共现脉络，无引用边

一句话：不引入 citation 数据，用概念邻居随时间的进入和离开构造“祖先到后代”的脉络。

方法：对一个概念，比较早期窗口和晚期窗口的邻居集合。只在早期出现、晚期消失的邻居是候选祖先；只在晚期出现的是候选后代。用共现强度和社区相似度排序，挖路径。

评估：时间顺序一致性、专家评分、案例检查。海报上写 association, not citation influence。

数据：不需要新数据。

风险：共现不是影响，结论要谨慎。适合做案例，不适合做强因果声明。

入口：`src/concept_life/mine.py`。

什么时候做：想要“脉络”故事但拿不到引用数据时的替代，一天。

## I-007 链路预测回测

一句话：用 T 年以前的图预测 T 到 T+2 年新出现的概念共现边。

方法：累计图，正样本是未来新出现的边，负样本是未来仍未出现的边。预测器用共同邻居、Adamic-Adar、Resource Allocation、Preferential Attachment，再加历史共现频率基线。

评估：AUC、AP，三个时间窗。

数据：不需要新数据。

风险：学术概念图稀疏，AUC 可能只有 0.6 到 0.7。如实报告，不要调测试集。

入口：`src/concept_life/predict.py`。

什么时候做：M3 的备选，一天。它和趋势预测共享时间切分，代码复用率高。

## I-008 时间感知检索桥接先导项目

一句话：同一个查询，在不同年份用当年的图做扩展，结果会不一样。它把当前项目和先导项目的 Acemap 搜索接起来。

方法：按年份过滤概念图，复用先导项目 `../kg_search/code/search.py` 的扩展逻辑，输出不同年代的扩展词和论文。

评估：定性，三个查询，每个查询选三个年份，人工看扩展词是否合理。

数据：不需要新数据。

风险：容易变成另一个检索项目，抢走主线时间。只作为 demo 的一个小面板。

入口：`src/concept_life/app.py`。

什么时候做：如果登记的题目是“Acemap 搜索增强”，用它做桥梁，半天。

## I-009 社区演化：出生、合并、分裂、消亡

一句话：每个快照跑 Louvain，匹配相邻快照的社区，追踪社区的生命周期。

方法：NetworkX 的 `louvain_communities`，固定 seed。相邻快照的社区用 Jaccard 重叠匹配，重叠超过阈值算同一个社区，多个旧社区对应一个新社区算合并，一个旧社区对应多个新社区算分裂。

评估：模块度、多次运行的稳定性、三到四个案例。

数据：不需要新数据。

风险：Louvain 有随机性，必须固定 seed 或跑多次取均值。

入口：`src/concept_life/graph.py` 和 `mine.py`。

什么时候做：M2 之后，一天。它是“研究地图”视觉的基础。

## I-010 概念别名合并

一句话：把指向同一个概念的不同 id 或不同写法合并，减少图谱碎片。

方法：字符串归一、编辑距离、词向量相似度、共享邻居相似度、Wikidata 对齐。先在高置信度上合并，低置信度人工抽查。

评估：三百对人工标注，算 precision 和 recall。

数据：不需要新数据，跨源时需要 Wikidata。

风险：过度合并会把不同概念揉在一起。保留合并证据，允许回滚。

入口：`src/concept_life/ingest.py`。

什么时候做：M1 数据清洗之后，一天。

## I-011 LLM 社区命名与趋势摘要

一句话：用一次大模型调用给每个社区起名，或者生成一段“这一期发生了什么”的摘要。

方法：把社区里度数最高的概念和代表论文标题拼成 prompt，让模型输出一个短名字或三句话摘要。结果缓存，不重复调用。

评估：人工抽查十个社区名字。

数据：需要 LLM API。

风险：模型会编。所有生成内容标注为 AI 生成，不进入定量结论。

入口：`src/concept_life/mine.py` 或 `app.py`。

什么时候做：展示层有余力时，半天。

## I-012 交互式研究地图

一句话：一个带年份滑块的研究地图，节点是概念，颜色是社区，大小是占比，点开是演化卡片。

方法：Streamlit 加 pyvis 或 Altair。只画度数最高的 300 个节点，否则会糊。所有数据预计算，演示时不联网。

评估：三个查询走一遍，确保不卡、不崩。

数据：不需要新数据。

风险：图太乱、现场网络不稳定。提前录 90 秒备份视频。

入口：`src/concept_life/app.py`。

什么时候做：M4 的核心，一天。

## I-013 黄金案例集

一句话：挑八个大家都认识的概念，人工标注大致的事件年份，用来做回归测试和海报素材。

方法：建议 Transformer、GAN、Diffusion、GNN、Federated Learning、SVM、MapReduce、Word2Vec。每个概念记录“语料首次出现年”“爆发年”“峰值年”，允许正负一年误差。测试断言事件检测的输出落在区间内。

评估：测试通过率。

数据：不需要新数据。如果某个概念在语料里覆盖太少，换一个。

风险：语料只是抽样，首次出现年不等于发明年。文档里写清楚。

入口：`configs/golden_cases.json`、`tests/test_golden.py`。

什么时候做：M2 之前，半天。先有测试再改规则。

## I-014 领域过滤与歧义概念停用词

一句话：只保留计算机科学的论文，过滤 `key (lock)`、`focus (optics)` 这种歧义概念。

方法：Acemap 的 `topics` 里有 `domain`、`field`、`subfield`，保留 `computer science`。对带括号消歧的概念名建停用词表。提高 `min_curr_count`。

评估：过滤前后的论文数、概念数、上升榜可解释性。

数据：不需要新数据。

风险：过滤太狠会丢掉跨学科论文。记录过滤前后的数量。

入口：`src/concept_life/ingest.py`、`configs/default.json`。

什么时候做：M1 的第一件事，半天。不做的话上升榜不能看。

## 备选项目方向

如果主线做不下去，或者组里想换一个更大的问题，下面两个方向在先导项目的复盘中讨论过。它们和当前主线共享 Acemap 数据和图构建代码，但研究问题不同。

### A. 图质量与语料驱动重建

问题：现有学术检索项目都在“用图”，没有人先问这张图配不配得上语料。先导项目量到 ConceptNet 只覆盖 Acemap 语料的 4.4%，于是用语料自己重建概念图，再回答三个问题。覆盖率和检索增益是什么关系，噪声率和增益是什么关系，能不能用查询特征预测“这条查询该不该启用增强”。

方法：共现图加 PMI，IDF 抑制 hub，Louvain 社区，链接预测补边，RRF 融合多路召回，学习排序替代手写权重。

评估：四十到六十个查询，pooling 后 LLM-as-judge 加人工抽检，nDCG@10、Recall@20，消融和噪声注入。

成本：两到三周，不适合五天项目。适合作为课程论文或后续研究。

### C. 图谱对齐与实体消解

问题：ConceptNet 和学术概念体系的词汇几乎不相交，纯字符串匹配只能把覆盖率从 4.4% 抬到 8.4%。能不能用嵌入、图结构和 Wikidata 做实体对齐。

方法：字符串归一、编辑距离、词向量、共享邻居、集体实体消解。

评估：三百对人工标注的 precision 和 recall，下游检索增益。

成本：一周左右，天花板较低。适合作为 A 的子模块，不适合单独做主线。

## 不建议做

- 纯 RAG 科研助手。表里有七组在做学术检索和 RAG，容易撞车。
- 个性化论文推荐。表里有五组推荐系统，且和当前数据资产关系不大。
- 完整的 DeepResearch Agent。五天做不完，演示风险高。
- 因果声明。共现和引用都不等于因果，措辞要保守。
