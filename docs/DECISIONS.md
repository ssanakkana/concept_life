# 决策记录

每条 `D-NNN`，包含背景、决定、备选方案、后果。任何影响数据 schema、评测口径、目录结构的决定都要写。

## D-001 以 Acemap 为主数据源

**背景**：先导项目已经有 Acemap 的缓存和解析代码，期末时间只有几天。

**决定**：M1 继续用 Acemap work search API 抓取，复用 `../kg_search/cache` 和请求格式。

**备选**：OpenAlex 的时间过滤更稳，年份覆盖更全，但需要新写抓取和字段映射。

**后果**：Acemap 的年份分布有滞后，citation 边缺失。需要引用数据时，按 DOI 去 OpenAlex 补，不影响主流程。

## D-002 概念节点用 id，不用名字

**背景**：Acemap 的 `display_name` 会变，同一个概念可能写成 “LLM” 和 “large language model”。

**决定**：所有聚合、图节点、事件表都用 concept `id` 做主键，`display_name` 只做展示。

**备选**：按名字归一化，或者用字符串相似度合并。

**后果**：id 稳定，但跨数据源对齐会麻烦。跨源时用 Wikidata 或名字做桥。

## D-003 所有频率用 share，不用原始计数

**背景**：语料每年在增长，原始计数会把“语料变大”误判成“概念变热”。

**决定**：概念频率定义为“该概念当年出现的论文数 / 当年论文总数”。上升分数用前后两个窗口的 share 差值和 share 增长率。

**备选**：用原始计数加年份固定效应，或者用 TF-IDF 式的年份归一化。

**后果**：share 更稳，但小概念会有高方差。用最小当前计数过滤。

## D-004 生命周期先用规则，再考虑模型

**背景**：时间只有几天，规则可解释、可调试、可直接画图。

**决定**：出生、爆发、峰值、衰退、复活、死亡都用阈值规则，写在 `mine.py` 和配置里。规则跑通后，再考虑用分类器替代或补充。

**备选**：直接上 HMM、changepoint detection、生存分析。

**后果**：规则可能漏掉复杂形状，但能快速出结果，且海报上讲得清。模型作为扩展。

## D-005 预测严格按时间切分

**背景**：趋势预测和链路预测很容易因为随机切分而虚高。

**决定**：训练只用 T 年以前的数据，测试用 T 到 T+2 年。报告至少三个时间窗的均值和方差。任何切分改动写新决策。

**备选**：随机切分，或者用全部数据拟合再回测。

**后果**：指标会更低，但可信。如果 AUC 只有 0.6，也如实报告。

## D-006 先做生命周期和趋势预测，链路预测与 citation 脉络作为扩展

**背景**：用户最初的想法是“概念如何兴起、发展、结局，预测未来新焦点”。链路预测和 citation 脉络是加分项，不是核心。

**决定**：M0 到 M3 先做概念时间线、生命周期事件、候选替代、趋势预测。链路预测和 citation 学习路径放到 M3 之后，只有在时间富余时做。

**备选**：一开始就做 citation 脉络或 RAG。

**后果**：核心故事完整，扩展有接口。不会因为 citation 数据拿不到而卡住。

## D-007 文档与 commit 双轨记录

**背景**：项目主要由 AI 实现，下一个接手的 AI 需要知道“为什么”和“哪里会踩坑”，commit 只能记录“改了什么”。

**决定**：每个任务在 `docs/WORKLOG.md` 留一条记录，commit message 带 worklog 编号。架构和评测口径的变更写 `docs/DECISIONS.md`，踩过的坑写 `docs/PITFALLS.md`。

**备选**：只靠 commit，或者只靠聊天记录。

**后果**：多一点写作成本，但交接、复现、写课程 AI 报告都能直接复用。

## D-008 想法池与当前计划分离

**背景**：扩展想法很多，但五天项目只能做一小部分。如果想法和当前计划混在一起，后来的 AI 会分不清“现在要做”和“以后可以做”。

**决定**：`docs/IDEAS.md` 只放未排期的扩展和备选方向，每条有 `I-NNN`、成本、数据依赖、评估、风险。`docs/PLAN.md` 只放当前里程碑和已认领任务。认领时把 ID 从 IDEAS 挪进 PLAN。

**备选**：所有想法都写进 PLAN，或者只放在聊天记录里。

**后果**：多一个文件，但优先级清晰，后来人不会误做未排期的功能。
